# codemap 플러그인 설계 스펙

작성일: 2026-11-05 / 상태: 검토 대기

## 1. 목적과 성공 기준

**목적:** 코드베이스를 Claude가 직접 읽고 분석해서 구조를 시각화하고, 만든 사람이 다른 사람에게 "이런 식으로 만들었다"고 설명할 수 있게 해 주는 플러그인. GitHub에 올려 두면 다른 사람이 Claude Code(및 Claude 앱 스킬)에서 설치해 바로 쓸 수 있어야 한다.

**성공 기준**
- 사용자가 두 줄의 설치 명령만으로 추가 설정 없이 사용할 수 있다.
- 산출물에 실제로 존재하는 파일·모듈만 등장하고, 확인하지 못한 내용은 추정으로 표시된다.
- 사용자가 쓴 언어(한국어/영어 등)로 결과물이 나온다.
- 샘플 결과를 보고 설치 전에 품질을 판단할 수 있다.

## 2. 범위

**첫 버전 포함**
- 아키텍처 개요 (C4 방식 줌인: 시스템 → 컨테이너 → 컴포넌트)
- 모듈/파일 의존성 그래프
- 마인드맵 (폴더·기능 계층)
- 설명 문서 (설계 개요 + 코드 읽는 순서 온보딩 가이드)
- 실행 흐름(시퀀스) 다이어그램 (sequence-flow)
- 산출물 갱신 (codemap-refresh): 코드 변경 후 낡은 부분만 다시 생성
- 발표용 요약 (present): 전체 결과를 핵심 5~7장 분량의 개요로 압축
- 출력 형식: Mermaid 마크다운과 인터랙티브 HTML을 기본으로 함께 생성 (`--no-html`로 HTML 생략; 2026-11-05 변경)

**첫 버전 제외 (이후 버전 후보)**
데이터 모델(ER), 상태 다이어그램, ADR, 용어집, 핫스팟 맵(Git 이력 필요), 변경 영향도, 정적 분석 스크립트, 자동화 CI 테스트

## 3. 핵심 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 분석 방식 | Claude가 직접 코드를 읽는 스킬 기반 | 설치물 없음, 모든 언어 지원, 설계 의도 설명 가능 |
| 내부 구조 | 기능별 스킬 7개 + 진입 명령 1개 (접근법 B) | 지침이 짧아 품질 안정, 부분 사용 가능, 확장 쉬움 |
| 출력 형식 | Mermaid 마크다운 + 기본 HTML(`--no-html`로 끔) | 바로 보기 좋은 결과를 기본으로 제공 (초기안은 선택적 HTML이었으나 사용자 요청으로 변경) |
| 언어 | 사용자 언어를 따라감 | 국내외 사용자 모두 설정 없이 사용 |
| 이름 | `codemap` | |

```
codemap/
├── .claude-plugin/
│   ├── plugin.json
│   └── marketplace.json
├── commands/
│   └── codemap.md                       진입 명령 /codemap
├── skills/
│   ├── architecture-overview/SKILL.md
│   ├── dependency-graph/SKILL.md
│   ├── mindmap/SKILL.md
│   ├── design-doc/SKILL.md
│   ├── sequence-flow/SKILL.md
│   ├── present/SKILL.md
│   ├── codemap-refresh/SKILL.md
│   └── _shared/
│       ├── mermaid-rules.md
│       ├── html-template.html
│       └── language-and-output.md
├── examples/                            샘플 프로젝트와 생성 결과
```

설치: `/plugin marketplace add <owner>/codemap` → `/plugin install codemap@codemap`

디자인 수정 지점: HTML 외형은 `html-template.html`, Mermaid 스타일은 `mermaid-rules.md`, 문서 구성은 각 `SKILL.md`. 구현 후 샘플 결과를 보고 다듬는다.

## 5. 동작 흐름

**1단계 프로젝트 파악 (`/codemap`이 1회 수행)**
폴더 구조 훑기 → 설정 파일로 언어·프레임워크 판별 → 진입점과 핵심 모듈 후보 추리기 → 짧은 "프로젝트 요약"을 만들어 네 스킬이 공유.

**2단계 스킬별 생성 (각각 독립 실행 가능)**
- architecture-overview: C4 단계별로 별도 Mermaid 다이어그램 + 한 줄 설명
- dependency-graph: 실제 import/require를 읽어 의존 방향을 그림. 노드가 많으면 폴더 단위로 묶고, 순환 의존은 표시
- mindmap: Mermaid mindmap으로 폴더·기능 계층 표현
- design-doc: 위 결과를 참조해 구조 개요, 핵심 설계 선택, 코드 읽는 순서를 서술
- sequence-flow: 사용자가 고른(또는 진입점에서 추린) 대표 시나리오 2~3개를 실제 호출 순서대로 시퀀스 다이어그램으로 그림. 코드로 따라가지 못한 구간은 점선·"확인 필요"로 표시
- present: 앞선 산출물만 입력으로 받아 발표용 요약(5~7장 분량, 장별 제목·핵심 한두 문장·넣을 다이어그램 지정)을 만듦. 새 분석은 하지 않음
- codemap-refresh: 기존 `docs/codemap/` 산출물에 기록된 기준 시점(생성 당시 파일 목록·핵심 해시 또는 커밋)과 현재 코드를 비교해 달라진 부분만 해당 스킬로 재생성. 사용자 수동 편집 구간은 보존하고 충돌 시 확인

**3단계 검증과 저장**
저장 전 Mermaid 문법 점검 → 확인 못 한 부분은 "추정"/"확인 필요"로 표시, 코드에 근거 없는 설계 의도는 단정하지 않음 → `docs/codemap/`에 저장 → HTML은 요청 시에만 `html-template.html`로 추가 생성.

대규모 저장소는 진입점에서 출발해 핵심 경로 위주로 읽고, 다루지 못한 범위를 문서 끝에 명시한다.

## 6. 오류 처리

- 코드가 없거나 너무 작음: 억지로 만들지 않고 안내
- 낯선 언어·구조: 추측 금지, 확인된 범위만 그리고 "확인 필요" 표시
- 대규모 저장소: 읽은 범위/못 읽은 범위 명시
- 기존 `docs/codemap/` 파일 존재: 덮어쓰기 전 사용자 확인
- Mermaid 문법 오류: 저장 전 점검에서 걸러 재생성
- refresh 대상 산출물이 없음: 갱신할 것이 없다고 알리고 `/codemap` 실행을 제안
- refresh 시 기준 시점 정보가 없거나 형식이 다름: 전체 재생성 여부를 사용자에게 확인
- present 입력 산출물이 부족함: 없는 산출물을 먼저 생성할지 사용자에게 확인

## 7. 품질 확인

- `examples/`에 크기·언어가 다른 샘플 저장소 2~3개(예: Python, TypeScript)를 두고 실제로 산출물 생성
- 체크리스트: Mermaid 렌더링 여부 / 존재하는 파일·모듈만 등장 / 요청 언어로 출력 / 미확인 부분 표시
- 생성 결과를 `examples/`에 함께 올려 설치 전 미리보기 제공
- 샘플 결과를 보며 템플릿과 규칙 파일의 디자인을 조정
- refresh는 샘플 저장소의 코드를 일부 수정한 뒤 달라진 부분만 갱신되는지로 확인
- 구현 순서: 산출물 형식이 굳은 뒤 codemap-refresh를 마지막에 구현 (기준 시점 기록 형식에 의존하므로)

## 8. 미결정 사항

- GitHub 저장소는 아직 없음. 구현 시작 전 또는 직후에 사용자가 `owner`를 정해 생성한다 (생성·push는 사용자 확인 후 진행).
- 라이선스 종류 (구현 계획 단계에서 결정)
