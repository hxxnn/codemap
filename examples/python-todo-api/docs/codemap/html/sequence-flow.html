      실제 코드를 따라가며 세 가지 시나리오를 그렸습니다. 고른 이유: (1) POST /todos는 가장 중심이 되는 쓰기 동작, (2) GET /todos는 저장소를 읽는 동작, (3) 빈 제목은 코드에 있는 유일한 오류 경로입니다. 열린 화살표(-))는 FastAPI 프레임워크가 내부에서 처리해 따라가지 않은 구간입니다.

      POST /todos — 할 일 추가

      클라이언트가 POST /todos로 제목을 보내면 create_todo()가 실행됩니다.

      라우트가 시각을 만들고 저장소에 넘기면, 저장소가 모델에게 객체 생성을 맡기고 모델이 다시 저장소에서 id를 받아 오는 순환 호출이 일어납니다. FastAPI가 요청을 라우트 함수로 연결하고 반환값을 응답으로 바꾸는 부분은 읽지 않았습니다. 또한 title이 쿼리 파라미터로 전달된다는 점도 FastAPI의 기본 동작에 대한 추정입니다.

      1. app/routes.py:create_todo — title.strip()이 비었는지 검사
      2. app/utils.py:now_iso — 현재 UTC 시각을 ISO 문자열로 반환
      3. app/storage.py:add_todo — Todo.create를 호출해 객체를 만들고 _TODOS에 추가
      4. app/models.py:Todo.create — storage.next_id()로 id를 받아 Todo 생성
      5. app/storage.py:next_id — len(_TODOS) + 1 반환
      6. app/routes.py:create_todo — todo.to_dict()를 반환
