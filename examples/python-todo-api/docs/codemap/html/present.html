      슬라이드 4: 어떻게 실행되나

      POST /todos는 시각 생성, 저장소 추가, 모델 생성, dict 변환 순서로 진행됩니다. 라우팅과 직렬화는 프레임워크 내부라 추적하지 않았습니다.

      슬라이드 5: 부분들의 의존 관계

      슬라이드 6: 핵심 설계 선택

      • 메모리 안의 저장소 모듈(app/storage.py): 재시작하면 데이터가 사라집니다. 이유는 코드에 없습니다. (추정)
      • 라우터 분리: app/routes.py의 라우터를 app/main.py에서 붙입니다.
      • 의도된 순환 import: app/models.py와 app/storage.py가 서로 호출합니다.

      슬라이드 7: 어디서부터 읽을까

      README.md, pyproject.toml, app/main.py, app/routes.py, app/storage.py 순서로 읽기 시작합니다.

      다루지 않은 범위

      각 산출물의 "다루지 않은 범위"를 따릅니다. 모든 소스와 README.md, pyproject.toml을 읽었고, 테스트와 배포 설정은 저장소에 없으며, FastAPI 내부 동작과 실제 서버 실행은 확인하지 않았습니다.
