      todo-api는 FastAPI로 만든 작은 할 일 관리 서비스입니다. 아래에서 시스템 맥락, 컨테이너, 컴포넌트 순서로 확대해 가며 구조를 보여 줍니다.

      1. 시스템 맥락

      flowchart LR
  n1["사용자 / HTTP 클라이언트"]:::external
  n2["todo-api (app/)"]
  n1 -->|"HTTP 요청"| n2
  classDef external fill:#E3F4F1,stroke:#0E8F83,color:#0B4F49

      사용자(HTTP 클라이언트)가 todo-api에 요청을 보내는 구조이며, 코드에서 확인된 외부 시스템은 없습니다(데이터베이스나 외부 API 호출 없음).

      실행은 README.md에 적힌 uvicorn app.main:app 한 프로세스이고, 데이터는 별도 DB 없이 같은 프로세스의 모듈 전역 리스트에만 보관됩니다.

      app/main.py가 앱을 만들어 app/routes.py의 라우터를 붙이고, 라우트는 app/storage.py와 app/utils.py를 부릅니다. app/storage.py와 app/models.py는 서로를 import하는 순환 관계이며 코드 주석이 "deliberate cycle"이라고 적고 있습니다(자세한 내용은 dependency-graph.md).

      다루지 않은 범위

      저장소의 소스 파일 app/main.py, app/routes.py, app/storage.py, app/models.py, app/utils.py와 README.md, pyproject.toml을 모두 읽었습니다. app/__init__.py는 비어 있습니다. 읽지 않은 범위는 없습니다.
