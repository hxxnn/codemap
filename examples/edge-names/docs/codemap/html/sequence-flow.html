      프로그램이 실제로 어떤 순서로 호출하는지 코드에서 따라가 두 가지 시나리오로 그렸습니다.

      프로그램을 실행해 모든 항목을 출력하기

      진입점 src/main.js가 실행되면 모듈을 불러오고 항목 목록을 받아 하나씩 출력합니다.

      sequenceDiagram
  participant M as src/main.js
  participant U as src/my utils.js
  participant L as src/데이터 로더.js
  participant O as 콘솔(stdout)
  M->>U: require 로 shout 가져오기
  M->>L: require 로 loadItems 가져오기
  M->>L: loadItems()
  L-->>M: 항목 배열 복사본
  loop 받은 각 항목
    M->>U: shout(item)
    U-->>M: 대문자 문자열
    M->>O: console.log(결과)
  end

      두 모듈은 맨 위에서 먼저 로드되고, 이후 반복문이 항목마다 변환과 출력을 수행합니다.

      1. src/main.js 맨 위에서 require("./my utils.js")로 shout를 가져옵니다.
      2. src/main.js에서 require("./데이터 로더.js")로 loadItems를 가져옵니다.
      3. src/main.js가 src/데이터 로더.js:loadItems를 호출해 items.slice() 복사본을 받습니다.
      4. for...of 반복에서 항목마다 src/my utils.js:shout를 호출합니다.
      5. 반환된 문자열을 src/main.js가 console.log로 출력합니다.

      항목 하나를 대문자로 바꾸기

      shout가 호출되면 문자열을 대문자로 바꾸고 느낌표를 붙여 돌려줍니다.

      sequenceDiagram
  participant M as src/main.js
  participant U as src/my utils.js
  M->>U: shout(text)
  Note over U: text.toUpperCase() 호출 (내장 메서드)
  U-->>M: 대문자 text 뒤에 느낌표

      이 함수는 다른 파일을 부르지 않고 JavaScript 내장 toUpperCase만 사용합니다.

      1. src/main.js가 src/my utils.js:shout에 항목을 넘깁니다.
      2. src/my utils.js:shout가 text.toUpperCase() + "!"를 계산합니다.
      3. 결과 문자열이 src/main.js로 돌아갑니다.

      오류 처리 경로(try/catch, 입력 검사)는 코드에 없어 세 번째 시나리오는 만들지 않았습니다.

      다루지 않은 범위

      소스 3개를 모두 읽었고 추적하지 못한 호출은 없습니다. src/데이터 로더.js는 경로에 한글이 있어 해시 안전 규칙을 통과하지 못해 sources에 넣지 못했습니다 (확인 필요)
