      notes-cli는 터미널에서 메모를 추가하고 목록으로 보는 작은 TypeScript 명령줄 도구이며, 아래에 세 단계의 확대 수준으로 구조를 그렸습니다.

      1. 시스템 컨텍스트

      flowchart LR
  user["터미널 사용자"]:::external
  env["환경변수 USER"]:::external
  sys["notes-cli (CLI 도구)"]
  user -->|"notes add / list"| sys
  env -->|"작성자 이름"| sys
  sys -->|"메모 출력"| user
  classDef external fill:#E3F4F1,stroke:#0E8F83,color:#0B4F49

      사용자가 notes 명령을 실행하면 도구가 환경변수 USER에서 작성자 이름을 읽고 결과를 터미널에 출력합니다(src/index.ts, src/user-profile.ts).

      2. 컨테이너

      flowchart LR
  user["터미널 사용자"]:::external
  subgraph proc["notes 프로세스 (Node.js, src/)"]
    cli["CLI 프로세스 (TypeScript, src/)"]
    mem["메모리 내 notes 배열 (src/notes-store.ts)"]
  end
  user -->|"명령 실행"| cli
  cli -->|"읽기/쓰기"| mem
  classDef external fill:#E3F4F1,stroke:#0E8F83,color:#0B4F49

      배포 단위는 package.json의 bin이 가리키는 단일 CLI 하나이고, 저장소는 별도 DB 없이 프로세스 메모리의 배열뿐이라 명령이 끝나면 메모는 사라집니다.

      3. 컴포넌트

      flowchart LR
  subgraph entry["진입"]
    idx["CLI 진입 (src/index.ts)"]
  end
  subgraph logic["로직"]
    store["메모 저장소 (src/notes-store.ts)"]
    prof["사용자 정보 (src/user-profile.ts)"]
    fmt["포맷터 (src/format.ts)"]
  end
  subgraph shared["공유"]
    types["타입 (src/types.ts)"]
  end
  idx -->|"addNote, listNotes"| store
  idx -->|"currentUser"| prof
  store -->|"formatNote"| fmt
  store -->|"Note"| types
  fmt -->|"Note"| types

      src/index.ts가 명령을 해석해 저장소와 사용자 정보 모듈을 부르고, 저장소는 출력 문자열 생성을 src/format.ts에 맡기며, Note 타입은 src/types.ts 한 곳에 정의됩니다.

      다루지 않은 범위

      tsconfig.json은 읽지 않았고, 빌드 산출물 dist/는 저장소에 없어 보지 못했습니다. 나머지 소스 5개는 모두 끝까지 읽었습니다.
