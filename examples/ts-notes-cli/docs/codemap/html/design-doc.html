      개요

      notes-cli는 터미널에서 메모를 추가(notes add "text")하고 목록을 보는(notes list) 명령줄 도구이며, README.md도 같은 사용법을 설명합니다. TypeScript 5.4 이상으로 작성되었고(package.json) 컴파일 대상은 ES2022, 모듈 방식은 CommonJS, strict 모드입니다(tsconfig.json). 런타임 의존성은 없고 개발 의존성은 typescript뿐입니다. 메모는 프로세스 메모리 배열에만 저장됩니다.

      구조

      프로젝트는 하나의 CLI 프로세스이고, src/ 아래 5개 파일이 진입점, 저장소, 포맷터, 사용자 정보, 타입으로 나뉘어 있습니다. 의존 방향은 위에서 아래로만 흐르며 순환은 없습니다. 자세한 그림은 architecture.md(세 단계 구조), dependency-graph.md(import 간선), mindmap.md(기능 지도), sequence-flow.md(add, list, 오류 경로의 호출 순서)를 보세요.

      요약하면 src/index.ts가 src/notes-store.ts와 src/user-profile.ts를 부르고, 저장소는 src/format.ts로 출력 문자열을 만들며, src/types.ts의 Note를 공유합니다.

      핵심 설계 선택

      1. 메모리 배열 저장을 작은 모듈 뒤에 숨김. src/notes-store.ts가 모듈 수준 배열 notes를 가지고 addNote와 listNotes만 내보냅니다. 효과: 호출부는 저장 방식을 몰라도 되지만, 프로세스가 끝나면 메모가 사라지므로 notes add 다음에 별도로 실행한 notes list에는 아무것도 나오지 않습니다. 이렇게 한 이유는 코드와 README.md에 적혀 있지 않습니다. 단순함을 위한 초기 단계 선택으로 보이지만 근거는 없습니다. (추정)
      2. 명령줄 파싱을 진입점 한 파일에서 직접 처리. src/index.ts가 process.argv.slice(2)를 구조분해하고 if / else if / else로 분기하며, 인자 처리 라이브러리를 쓰지 않습니다(package.json에 런타임 의존성 없음). 효과: 명령이 두 개뿐이라 한 화면에서 전체 흐름이 보입니다. 라이브러리를 쓰지 않은 이유는 코드에 나와 있지 않습니다. (추정)
      3. 공유 타입을 별도 파일로 분리. src/types.ts가 Note(id, text, author)만 정의하고, src/notes-store.ts와 src/format.ts가 이를 가져다 씁니다. 효과: 저장소와 포맷터가 서로를 거치지 않고 같은 형태를 공유합니다.
      4. 표시 형식을 순수 함수로 분리. src/format.ts의 formatNote는 Note를 받아 #id 본문 (작성자) 문자열만 돌려줍니다. 효과: 출력 형식을 바꿀 때 저장 로직을 건드리지 않아도 됩니다. 저장소는 notes.map(formatNote)로 이를 사용합니다.
      5. 환경 의존을 한 함수에 격리. src/user-profile.ts의 currentUser가 process.env.USER를 읽고 없으면 "anonymous"를 반환합니다. 효과: 환경 변수 접근이 이 한 곳에만 있어 나머지 코드가 process.env를 직접 알 필요가 없습니다.
      6. 저장소가 문자열 목록을 반환. listNotes가 Note가 아니라 포맷된 string[]을 돌려주므로 저장소가 표시 형식에 의존합니다(src/notes-store.ts가 src/format.ts를 가져옴). 효과: 진입점은 단순해지지만 저장과 표시가 한 모듈에서 만납니다.
