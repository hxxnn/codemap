      개요

      notes-cli는 notes add "text"로 메모를 추가하고 notes list로 보는 명령줄 메모 도구입니다(README.md). TypeScript로 작성되었고 package.json의 bin이 notes를 dist/index.js에 연결하며, 빌드는 tsc를 씁니다. 런타임 의존성은 없고 개발 의존성은 typescript뿐입니다.

      구조

      진입 파일 src/index.ts가 명령을 나누고, 저장소(src/notes-store.ts), 사용자 정보(src/user-profile.ts), 포맷터(src/format.ts), 타입(src/types.ts)이 각각 한 가지 일만 맡습니다. 세 단계 다이어그램은 architecture.md, import 관계는 dependency-graph.md, 파일별 트리는 mindmap.md, 호출 순서는 sequence-flow.md에 있습니다. 의존 방향은 한쪽으로만 흐르며 순환은 없습니다.

      핵심 설계 선택

      1. 메모리 내 저장소 — src/notes-store.ts의 모듈 전역 배열 notes에 보관합니다. 효과: 프로세스가 끝나면 메모가 사라지므로 add 뒤 list를 다른 실행에서 해도 비어 있습니다. 이유는 코드에 적혀 있지 않습니다. (추정: 프로토타입이라서)
      2. 진입 파일에서 명령 분기 — src/index.ts 한 파일에서 process.argv를 직접 if/else로 나눕니다. 효과: 명령이 둘뿐이라 단순하지만, 명령이 늘면 이 파일이 커집니다.
      3. 출력 형식 분리 — formatNote()를 src/format.ts로 따로 두고 저장소가 map(formatNote)로 부릅니다. 효과: 출력 모양을 저장 로직과 독립해 바꿀 수 있습니다.
      4. 작성자는 환경변수에서 — currentUser()가 process.env.USER ?? "anonymous"를 반환합니다(src/user-profile.ts). 효과: 로그인 개념 없이 OS 사용자 이름을 씁니다.
      5. 타입 한 곳 정의 — Note 인터페이스를 src/types.ts에만 두어 저장소와 포맷터가 함께 씁니다.

      읽는 순서

      1. README.md — 도구의 목적과 사용법을 먼저 확인합니다.
      2. package.json — bin과 빌드 스크립트로 실행 방식을 봅니다.
      3. src/index.ts — 실행이 시작되는 곳이며 add/list 분기를 봅니다.
      4. src/notes-store.ts — 메모가 어디에 어떻게 쌓이는지 봅니다.
      5. src/format.ts — 출력 한 줄의 모양을 확인합니다.
      6. src/types.ts — Note의 필드 3개를 확인합니다.
      7. src/user-profile.ts — 작성자 이름을 얻는 방식을 봅니다.

      다루지 않은 범위

      tsconfig.json과 빌드 산출물 dist/는 읽지 않았습니다. 소스 5개, package.json, README.md는 모두 읽었습니다.
